# Voice assistant transformed into live agent with direct execution

The voice assistant was a dictation-then-confirm widget: speak, review text, click "Send to AI", review parsed intent, click "Execute". This change removes the intermediate steps entirely. The mic button now activates a continuous listening loop that auto-sends each recognized utterance to the Cloud Function, dispatches the returned action (navigate, open modal, fill field, confirm, or execute order directly), speaks the result via TTS, then reactivates the microphone. The Cloud Function prompt was extended with four new action types (`navegar`, `abrir_modal`, `llenar_campo`, `confirmar`) and a state protocol (`estadoAgente` + `modalTipo`) so the LLM knows whether a modal is open and interprets speech accordingly.

Watch for: the stop-word "para" will fire on any utterance that starts with the most common Spanish preposition (confirmed); direct execution path writes Firestore orders without user confirmation, relying entirely on LLM confidence (confirmed); the Cloud Function endpoint has no authentication — any caller can invoke it and generate orders (confirmed, pre-existing but now higher risk).

**Verdict**: NEEDS_CHANGES

## High-level view

The interaction model shifted from five-step (record → review → send → review → execute) to zero-step (speak → done). Continuous listening via `SpeechRecognition` with `continuous: false` means each final result triggers an auto-send, TTS response, then mic restart. The design relies on an 800ms delay between recognition sessions to avoid overlap with TTS playback, which is fragile — if speech synthesis finishes in less than 800ms or takes more than 800ms, the timing assumptions break.

The Cloud Function prompt grew by ~100 lines to describe a state machine. The frontend sends `estadoAgente` and `modalTipo` alongside the transcript, letting the LLM produce contextual responses. The LLM is the sole decision-maker for whether an order is "complete enough" to execute directly — there is no client-side validation gate between the LLM's JSON and Firestore writes.

Field filling works by DOM manipulation: finding input elements by known selectors and programmatically setting values. For items, the code pushes into `estado.itemsOrden` then clicks `#o-add` — a dual-write that creates orphan rows because the button handler also appends to state.

The "para" stop-word will deactivate the agent whenever the user says any sentence starting with "para" (e.g., "para el frente 3B"), which is extremely common in Colombian Spanish. And the agent state (`en_modal` vs `libre`) has no listener for external modal close, so manual dismissal permanently desyncs the agent.

## "para" stop-word collision

The stop-word list includes `'para'`. The detection function:

```javascript
function esStopWord(texto) {
  const t = normTxt(texto);
  return STOP_WORDS.some((sw) => t === normTxt(sw) || t.startsWith(normTxt(sw)));
}
```

The `t.startsWith(normTxt(sw))` branch means any transcript beginning with "para" — "para el frente 5", "para Pedro Gomez", "para el tablero del tercer piso" — will deactivate the agent. In Colombian Spanish, "para" is arguably the most frequent sentence opener when dictating destinations or purposes. This will make the agent unusable for common commands. The fix is either exact-match only (`t === normTxt(sw)`) or replacing "para" with a multi-word phrase like "para agente" or "detente agente".

## Direct Firestore writes without confirmation gate

`ejecutarDirectoIA` resolves materials by substring match against `estado.materiales`, validates stock, then calls `registrarOrden` — which writes to Firestore, updates local state, and decrements inventory. There is no "are you sure?" step.

Speech recognition frequently produces partial or garbled transcripts (especially in noisy warehouse environments), and substring matching (`normTxt(m.nombre).includes(normTxt(it.nombre))`) can match the wrong material. "Cable 12" matches "Cable #12 AWG Rojo" but also "Cable #12 AWG Negro" — `.find()` returns the first match, which may not be what the user intended. A wrong dispatch is a real inventory discrepancy that requires manual correction.

The old code opened a pre-filled modal and required the user to click "Ejecutar" — a deliberate confirmation gate that this change removes.

## Item field-fill dual-write creates orphan rows

In `llenarCampoPorVoz` when `campo === 'item'`:

```javascript
estado.itemsOrden.push({ _id: Date.now() + Math.random(), materialId: mat.id, cantidad: itemCantidad, _filtro: '' });
const addBtn = $('#o-add');
if (addBtn) addBtn.click();
```

The `#o-add` button's click handler (defined in `modalOrden`) also pushes a new entry to `estado.itemsOrden` and re-renders. Two rows get added: one from the direct push (with correct data) and one from the button click (empty). The code then tries to fill "the last row" in the DOM, which is the empty one from the button click. The net effect: one ghost row in state, one empty row visible in the UI, and the select/input assignments target the wrong row.

## TTS-to-mic handoff timing

The flow is: `enviarTextoAlAgente` → `despacharAccionIA` → `hablarAgente` (await) → return → `finally` block → `reactivarMicrofono` (800ms delay). On Electron builds where Chromium's TTS is backed by system voices, `onend` sometimes never fires (known Chromium bug). The 15-second safety timeout then resolves the promise, but during those 15 seconds the mic stays off and the agent appears frozen.

A more robust approach: poll `speechSynthesis.speaking === false` in a short interval rather than relying on the `onend` event, or use the Electron `tts` module if available.

## State desync when modal is closed externally

`asistente.estadoAgente` is set to `'en_modal'` when the agent opens a modal, but the modal can be closed by the user clicking the X button or pressing Escape. No listener resets `asistente.estadoAgente` back to `'libre'` on external close. Once desynced, the LLM receives `estadoAgente="en_modal"` and interprets all subsequent commands as field-filling, making the agent unresponsive to navigation or new orders until the user says a stop word and restarts.

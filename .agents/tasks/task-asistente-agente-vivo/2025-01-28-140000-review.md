# Live voice agent — v3 final review

Both v2 concerns are resolved. `ejecutarDirectoIA` now calls `actualizarHerramientaDespacho` in a post-save loop for tool items on salida dispatches, matching the modal handler's behavior. `confirmarModalPorVoz` observes modal close via a 300ms polling interval before announcing success — if the modal hasn't closed within 10 seconds, it announces failure instead. State reset (`estadoAgente = 'libre'`) only happens inside the interval callback after confirming `#modal.hidden === true`, so the false-success path from v2 is eliminated.

Watch for: `confirmarModalPorVoz` returns immediately (fire-and-forget observation), so the mic reactivates while the save is still in flight — not a functional bug since `estadoAgente` remains `'en_modal'` until success, but a user speaking during the save window gets another `en_modal`-scoped interpretation rather than a "please wait" (possible, low severity).

**Verdict**: APPROVED

## High-level view

The tool-tracking fix adds 7 lines mirroring the modal handler's existing pattern: iterate resolved items after `registrarOrden`, check `mat.esHerramienta`, call `actualizarHerramientaDespacho` with the same arguments (materialId, responsable, frente, tipo).

The `confirmarModalPorVoz` fix replaces synchronous click-then-announce with an observation loop. The loop polls `$('#modal').hidden` every 300ms. On detection of close (success signal from the existing save handler), it resets agent state and speaks confirmation. A 10-second timeout catches failures — validation rejects, Firestore errors, or network hangs all manifest as "the modal didn't close," which triggers the error announcement. The 10s timeout is generous for a Firestore write (typical <1s), but safe against slow networks at a construction site.

## Observation-based confirm replaces fire-and-forget

The previous implementation:

```javascript
btnGuardar.click();
asistente.estadoAgente = 'libre';
return hablarAgente('Orden generada exitosamente.');
```

The current implementation:

```javascript
btnGuardar.click();
const checkCierre = setInterval(async () => {
  const modal = $('#modal');
  if (modal && modal.hidden) {
    clearInterval(checkCierre);
    asistente.estadoAgente = 'libre';
    asistente.modalTipo = null;
    await hablarAgente('Orden generada exitosamente.');
  }
}, 300);
setTimeout(() => {
  clearInterval(checkCierre);
  if (!$('#modal').hidden) {
    hablarAgente('Hubo un problema al generar la orden. Revisa los datos.');
  }
}, 10000);
return Promise.resolve();
```

The `return Promise.resolve()` means `await confirmarModalPorVoz()` in the dispatcher resolves immediately, and the observation continues independently. The caller's `finally` block then reactivates the mic. The alternative — returning a promise that resolves only on modal close or timeout — would block mic reactivation for up to 10 seconds on failure, freezing the agent. The current design keeps the agent responsive at the cost of a brief window where speech during save is misrouted. Given that the save typically completes in <1s and the user hears the button click as implicit feedback, this is a pragmatic trade-off.

# Vertex AI migration with enhanced electrical prompt and view-context awareness (v2)

This change migrates the Cloud Function from the `@google/generative-ai` SDK to direct Vertex AI REST calls via `google-auth-library`, vastly expands the SYSTEM_PROMPT with 30+ Colombian electrical jargon terms, explicit circuit desglose rules (120V and 220V variants), number interpretation, and default calibre fallback logic, and wires up the frontend to send `vistaActual` so the model can make context-aware action decisions. The CSP is pinned to the specific Cloud Run endpoint and the prompt architecture properly separates system instructions from user input.

All five issues from the v1 review have been addressed. However, the outer catch block still leaks `error.message` to the client, and the model identifier `gemini-3.7-flash` doesn't match any known publicly available model.

**Watch for:** The outer catch block still sends `error.message` to the client (confirmed). The model ID `gemini-3.7-flash` is not a recognized Vertex AI model name — this will produce 404s at runtime unless it's a private/preview model enabled on the project (likely). The raw `textResp` fragment is returned to the client in the JSON-parse fallback path (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The v1 review's primary structural concern — prompt injected as a user turn — is fully resolved. The Vertex AI request now uses `systemInstruction` for the prompt and `contents` for user input.

Two residual issues remain. The outer `catch` block at line 227 still forwards `error.message` to the client — this is the generic Node.js exception handler, so the message could contain stack fragments, file paths, or auth-library internals depending on the failure mode. The model identifier `gemini-3.7-flash` doesn't correspond to any publicly documented Vertex AI model; the commit history shows six model changes across six commits, and the current value will fail at deployment unless the project has a preview model enabled under that name.

The fallback path when JSON parsing fails returns `raw: textResp.substring(0, 300)` directly to the client — in the worst case a truncated echo of system instructions if the model hallucinates its prompt back.

## Outer catch error leakage

The Vertex AI non-200 path was correctly fixed — it now returns a generic message. But the outer try/catch still passes through the raw exception message:

```js
} catch (error) {
  console.error('Error en asistente:', error);
  res.status(500).json({ error: 'Error interno: ' + (error.message || 'desconocido') });
}
```

If `google-auth-library` throws (token refresh failure, missing credentials, network timeout), `error.message` may contain service account emails, project metadata, or internal URLs. The fix is identical to what was done for the Vertex AI error path — send a fixed string to the client.

## Model identifier uncertainty

The commit history reveals six model changes across six commits, settling on `gemini-3.7-flash`. No Vertex AI documentation or Model Garden listing references this identifier publicly. The FEAT-001 findings note "confirmado que funciona en el proyecto" — this suggests manual verification, but preview models can be deprecated without notice. Reviewers should confirm the model is stable, or pin to a GA model like `gemini-2.0-flash`.

## Parse-failure raw output to client

When Gemini responds with non-JSON, the fallback produces:

```js
json = { accion: 'error', confianza: 0, mensaje: 'No pude interpretar la respuesta.', raw: textResp.substring(0, 300) };
```

The `raw` field goes directly to the client. In the worst case this is a truncated echo of the system prompt. Since the prompt contains project details and business rules, this represents a minor information disclosure. Log `raw` server-side and omit it from the client response.

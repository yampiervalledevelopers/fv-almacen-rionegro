# Vertex AI migration with enhanced electrical prompt and view-context awareness (v3 — final)

This change migrates the Cloud Function from the `@google/generative-ai` SDK to direct Vertex AI REST calls via `google-auth-library`, vastly expands the SYSTEM_PROMPT with 30+ Colombian electrical jargon terms, explicit circuit desglose rules (120V/220V), number interpretation, and default calibre fallback, and wires up the frontend to send `vistaActual` so the model can make context-aware action decisions. CSP is pinned to the specific Cloud Run endpoint. Prompt architecture properly separates system instructions from user input via `systemInstruction` field.

All issues from v1 (5) and v2 (3) have been addressed.

**Watch for:** No blocking concerns remain. The `location: 'global'` Vertex AI routing is unusual but valid for this model (possible — worth confirming it resolves in production).

**Verdict**: APPROVED

## High-level view

The prompt uses `systemInstruction` for the instruction block with user input isolated in a separate `contents` turn. Both error paths return generic messages to the client while logging details server-side. The parse-failure path no longer leaks raw model output.

The SYSTEM_PROMPT covers all three wiring configurations with a default calibre fallback, maps each `vistaActual` value to appropriate action types, and includes ~35 Colombian electrical terms. The `vistaActual` const is read once and reused. The assistant panel is on `document.body` with the mic button in the always-visible topbar.

The CSP is pinned to `https://asistente-5lyachxl4a-uc.a.run.app` — no wildcards, no leftover entries.

## Vertex AI location: 'global'

The `LOCATION` constant is `'global'` rather than a regional endpoint like `us-central1`. The commit history (50f404a) indicates this was deliberate after testing. The Vertex AI API accepts `global` and routes to the nearest region, but availability and quota behavior may differ from a pinned region under load. Not blocking, but worth monitoring after deployment.
